# 004 조사 기록 — 사진 너머의 위기 (쿠바 미사일 위기의 첫 대응, 1962)

> 상태: 확정. 아래 검증과 화면 확인을 완료했다. `docs/EPISODE_GUIDE.md`와 `docs/templates/research.template.md`에 따랐다.
> 판단 시점: 1962년 10월 20~21일 워싱턴. 며칠간의 검토를 거쳐 해상 조치를 먼저 시행하고 공개 설명을 준비하던 장면을 압축했다. 선박 차단의 실제 발효 전이다. 26~28일 메시지·비밀 전달·정찰기 격추·합의는 공개 화면에만 나온다.
> 카드 문장은 실제 발언의 인용이나 한 회의의 의사록이 아니다. 저장소의 자문관 다섯 역할에 여러 참모의 보고·의견을 배분한 재구성이다. ‘시종’은 대통령에게 실제 그런 직책이 있었다는 뜻이 아니며, ‘재무’ 카드도 딜런의 실제 발언으로 읽어서는 안 된다.

## 관계도 (`map.svg`)

`docs/templates/relation-map.template.svg`의 문법을 사용했다. A·B는 큰 원, D는 중간 원, C는 작은 원이다. 이는 정성적 국력 구분이지 무기 수나 경제 규모의 비율이 아니다. 배치는 실제 지리와 다르게 했다.

- B→C 흐린 점선은 #2·#5·#12의 해상 무기 반입이다.
- A→C 잉크 실선은 대응을 검토하는 압박 방향이며 아직 결정하지 않은 공습·상륙을 실제 시행한 군사 진군처럼 표시하지 않는다.
- B–D의 접촉은 #34의 육상 국경이다. A와 C는 가까워도 바다로 갈라져 있으므로 원을 붙이지 않는다. B·C의 점선 원은 바다 건너 세력, D는 B와 접한 동맹국이라는 설명이다.
- 해안선·실명·연도는 넣지 않았다. 전략무기·사진 정찰·핵탄두라는 기술적 정보는 판단의 비용을 이해하기 위한 의도된 단서다. 그 정보만으로 특정 국가·지명을 직접 적지는 않는다.

## 게임 장치 (사실이 아님)

- 6회 질문·18장 카드·8개 세부 준비는 구성 장치다. 대통령이 이 문구 그대로 여덟 항목을 체크했다는 기록이 아니다.
- **c15 오보**: 동맹국 설명의 담당자와 사진 전문가가 따로 움직인다고 전한다. S5의 동행 계획을 잘못 옮길 법한 가상 보고다. 실제 유포를 입증한 자료는 없다. 동맹국의 찬반이나 증거의 실재 자체를 바꾸지 않는다.
- **c16 오보**: 20일 토론에 나온 약 7시간을 공통 승인 기준으로 옮긴다. 논의와 확정의 혼동을 재구성했으며 실제로 그런 오보가 돌았다고 주장하지 않는다. 공격 명령 발령이나 공격 성공으로 바꾸지 않는다.
- 오보는 두 장에만, 각각 신뢰도 0.9로 둔다. 핵탄두의 존재·부재, 공습의 전면 성공, 상대 반응 같은 핵심 불확실성은 가상 오보로 뒤집지 않는다.
- c11의 지속 비용, c09의 제3국 설득 문제, 상륙 뒤 주민 보호·통치 부담에 관한 반론은 #9~#18·#21의 사실을 바탕으로 재구성한 정책 의견이다. 당시 제출된 정량 예산이나 여론 조사인 것처럼 제시하지 않는다.
- `limited_strike`는 실제 논의된 제한 표적 공습을, `island_landing`은 실제 준비된 공습 이후 상륙을 분리한 가상 방침이다. 군사적으로 완전히 분리된 실행 단계라는 뜻은 아니다. 공격 범위가 넓어질 문제를 반론으로 드러낸다.
- `opening_offer`는 S6 및 S2·S5의 기지 조정·협상 논의를 바탕으로 한 초기 제안 대안이다. 27일 제안을 20~21일에 이미 받았던 것처럼 쓰지 않는다.
- 반사실 세 개는 당대의 구체적 우려와 계획을 근거로 가능한 결과를 추정한다. 어느 대안도 핵전쟁·즉시 합의·무혈 점령을 필연으로 예측하지 않는다.
- 방침별 무조건 반론 두 개씩과 조건부 반론 두 개를 두었다. 실제 방침도 기존 무기와 현장 충돌이라는 두 번째 문제를 피하지 못한다.

## 검증

- `npm run validate`: 001~004 모두 오류 0·경고 0. 스키마·참조·마스킹 누출·출처 필수 검사를 통과했다.
- `npm run check-urls`: 최종 출처 URL 44개 모두 HTTP 200, 실패 0·경고 0. 모든 도메인이 허용 목록에 있다.

- `npm run build`: 시나리오 생성·TypeScript·Vite 빌드 통과.
- 실제 반론 엔진으로 4방침 × 256개 세부 준비 조합 = 1,024개를 확인했다. 모든 조합에서 반론이 2~4개 나온다.
- `npm run dev`에서 1920×1080 데스크톱과 393×852 모바일(DPR 3) 각각 네 방침을 끝까지 진행했다. 정보 없는 질문의 횟수 보존, 질문 6회, 새로고침 복구, 세부 준비 선택, 반론, 공개, 비교표 9행·연표 8개·반사실 3개, 인물 사진 로드·기록 저장을 확인했다.
- 정체 공개 전 공개 JSON·실제 지도·초상 요청이 없었다. 8회 완주 중 화면 가로 넘침·브라우저 예외·HTTP 오류는 모두 0이었다.
- 관계도·공개 지도 및 모바일·데스크톱 공개 화면 캡처를 확인했다. 플로리다 북동부의 화면 경계점도 최종 그림에서 바로잡았다.
- SVG XML·팔레트·외부 이미지/스크립트 부재, 초상 JPG의 4:5·폭 제한, 비교표 주석·요약·연표의 글자 수 제한을 별도로 확인했다.
